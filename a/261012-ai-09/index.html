"에이전트는 예측 못 해도 통제 계층은 달라야"…멀티 에이전트 실패 잡는 평가법

데이터 엔지니어 슈화 쉬가 벤처비트 기고에서 멀티 에이전트 시스템은 각 에이전트가 제대로 작동해도 전체로는 실패할 수 있다고 지적했다. 오류는 에이전트 간 인계, 공유 상태의 변형, 서로를 기다리는 교착(데드락)이나 진전 없이 주고받기만 하는 라이브락에서 생긴다. 같은 모델을 쓰는 에이전트들은 서로의 실수를 잡기보다 같은 실수를 반복하기 쉽다.

글쓴이는 에이전트 간 상호작용을 RAG 파이프라인처럼 단계별로 평가하자고 제안한다. 먼저 에이전트 순서, 입출력, 인계 내용, 라우팅 결정, 상태 변화, 도구 호출, 재시도, 지연과 비용까지 전체 실행 기록을 남긴다. 그다음 워크플로 완료율·교착률, 인계 맥락의 정확도·재현율, JSON 스키마 검증 성공률, 상태 관리자의 제약 보존율과 요약 충실도 등을 지표로 삼는다.

에이전트마다 다른 모델을 쓰고 실패 상관관계를 측정해 '모델 단일 문화'를 피하라는 조언도 담겼다. 목표는 LLM을 결정적으로 만드는 게 아니라 에이전트 행동을 보이게, 측정 가능하게, 경계 안에서 복구 가능하게 만드는 것이라고 강조했다.
